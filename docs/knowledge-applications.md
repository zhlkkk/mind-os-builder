# 知识驱动应用与内容流水线

本文描述已经确定的演进方向，不代表当前版本已经实现对应命令。目标是在同一个本地知识底座上，自动编排选题、文字、卡片、图片、音频、视频和发布包，也允许用相同模块构建其他知识库或知识图谱应用。

## 核心原则

“确定性流水线”不等于“模型每次生成相同内容”。确定性来自控制面：输入快照、Schema、阶段状态、来源引用、路径、hash、审批、重放和提交行为都可验证；选题判断、写作、视觉创意和脚本生成仍由外层 Agent 完成。

- Skill 描述语义任务、质量标准和提示词。
- Agent 选择主题、角度、结构、表达和媒体方案。
- CLI 准备上下文，验证结构与来源，管理批次并显式提交。
- 外部 Adapter 调用图片、语音、视频、渲染或发布工具。
- Job 声明阶段入口与调度提示，不绑定具体 Agent 运行层。

## 两个共享模块

### Knowledge Pack

Knowledge Pack 是知识应用的读取接口。它从指定 vault 快照中准备一个有界上下文，至少记录：

- 来源页面、稳定标识、更新时间和内容 hash。
- 选定页面之间的 wikilink、标签、实体或其他图关系。
- 查询范围、时间窗口、排除规则和截断说明。
- 尚未解决的红链、证据缺口和过期信号。

第一版直接从 Markdown、frontmatter 和 wikilink 构建，不要求图数据库。未来接入图存储时使用 Adapter 满足同一接口，不能迫使 Skill 理解底层查询语言。

### Artifact Manifest

Artifact Manifest 是所有生成结果的提交接口。文章、卡片、图片和视频都以同一种谱系描述登记：

- 所属选题、目标受众、渠道和内容类型。
- 使用的 Knowledge Pack、来源主张和输入基线。
- Skill、提示词、模板和 Adapter 的版本或标识。
- 候选文件、媒体元数据、内容 hash、费用与生成时间。
- preview、approved、applied、noop、blocked 等稳定状态。

Manifest 不保存密钥，也不把模型草稿当成事实。CLI 根据 Manifest 校验文件、引用、路径与基线，再决定是否允许提交。

## 第一条应用流水线：选题到发布包

### 1. 选题

CLI 从知识索引、近期采集、Tech Radar、研究报告和历史发布记录准备 Knowledge Pack。Agent 返回结构化选题候选，包括受众、价值、角度、时效性、证据来源和与历史内容的重复判断。CLI 要求每个候选都有明确决定，并提交已批准选题。

### 2. 内容规格与草稿

Agent 把已批准选题转换为 Content Spec，明确主张、结构、引用、渠道、长度和需要的资产。文章正文、短摘要、卡片文案及音视频脚本从同一 Content Spec 派生，避免各渠道分别生成后互相矛盾。

CLI 不评价文风，只校验 Schema、引用闭包、来源基线、目标文件和同名冲突。草稿在 preview 中可比较，显式 apply 后才进入 vault 的输出区域。

### 3. 多模态资产

Agent 生成卡片布局说明、图片提示、分镜、旁白和字幕等结构化资产规格。外部 Adapter 调用具体工具并返回产物；CLI 校验格式、尺寸、时长、字幕关联、hash 和 Manifest 完整性。

卡片、图片、语音和视频先分别采用显式 Adapter。只有同类媒体出现两个真实实现并共享稳定行为后，才抽取公共媒体接口。

### 4. 渠道发布包

Channel Adapter 把规范内容和资产渲染为公众号、小红书、网站、播客或视频平台需要的文件包。第一阶段只生成可检查的发布包，不自动操作外部账号；未来即使支持发布，也必须单独声明网络、账号、费用和不可逆副作用，并保留人工确认策略。

### 5. 反馈回流

发布记录、人工修改和渠道指标可以形成新的候选材料，但不能直接改写 Wiki 事实。Agent 先区分事实、表现数据和创作偏好，CLI 再按既有 ingest/commit 契约提交经过审核的知识或规则更新。

## 其他知识应用

新的应用应复用“Knowledge Pack -> Agent 决策 -> Artifact Manifest -> CLI commit”接口。例如：

- 根据个人知识图谱生成每日简报、学习路径或复习计划。
- 从研究与实体关系生成专题地图、时间线和比较报告。
- 为项目生成 FAQ、决策记录、风险雷达和上下文包。
- 从书籍、笔记和实践记录生成课程、讲义或训练题。
- 为团队知识空间生成新人导航、会议准备和跨项目关联。

如果一个应用只需要新的判断方式或输出格式，应新增 Skill、Schema 或 Adapter，不应新增第二套核心运行时。

## 可验证里程碑

1. **选题闭环：**合成 vault 离线完成 Knowledge Pack、选题决策、preview、apply 和 noop。
2. **文字与卡片：**同一 Content Spec 生成文章和卡片包，所有主张可追溯到来源页面。
3. **媒体资产：**至少跑通一个图片 Adapter 和一个音频或视频 Adapter；缺失依赖时不产生半成品。
4. **流水线恢复：**Job 可由任意 Agent 宿主逐阶段运行，中断后从最后一个已提交 Manifest 恢复。
5. **产品外壳：**本地界面只消费 CLI JSON、Manifest、文件 diff 和 Job 状态，提供预览、审批与运行记录。

每个里程碑都必须保留 preview、显式 apply、路径保护、来源基线、幂等和合成离线测试。外部模型、媒体工具和渠道账号始终是可选依赖。
