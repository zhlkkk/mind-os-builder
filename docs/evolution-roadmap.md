# 演进路线

路线图描述下一步的产品方向，不代表当前版本已经提供这些能力。每一阶段都保留三个不变量：Skill 负责语义判断，CLI 负责确定性校验和提交，vault 默认由用户本地持有。

## 当前基础：可运行的公开参考实现

当前版本已经具备：

- 从空目录初始化 Wiki 与 Book Base。
- OpenCLI Twitter、Folo RSS 两阶段采集。
- Distill 五角色、Tech Research、Tech Radar。
- 六种 Agent 宿主的 Skill 安装示例。
- 声明式 Jobs、可选 stdio MCP、合成离线完整旅程。
- npm 打包、架构审计、隐私与发布审计。

当前重点是让目录、文档、契约和实现一致，不扩大 Provider 或产品表面。

## 下一阶段：让扩展可复制

目标是让贡献者不修改核心也能增加真实能力：

- 发布 Provider 作者指南，明确 argv、规范化记录、游标、错误码和测试夹具。
- 为新 Skill 提供最小模板、prompt 拆分约定和结构化提交示例。
- 扩充 MCP 与 CLI 的能力一致性测试，但仍采用显式工具清单。
- 为 Job 增加更多宿主示例，例如 cron、launchd 与 Agent 平台配置。
- 建立契约兼容矩阵和版本迁移说明，避免静默破坏已有 Agent 工作流。

Provider 数量增长时，先增加显式适配器和契约测试；只有至少两个实现共享同一稳定行为时才抽取公共接口，不建设自动插件注册中心。

## 确定方向：知识驱动的内容与应用流水线

第一个知识应用是从 vault 自动生成选题和多模态内容。自动化的是可恢复、可审计的流水线，不是让 CLI 直接调用模型：

1. 从 Wiki 索引、wikilink、frontmatter、Tech Radar 和近期素材准备带基线的 Knowledge Pack。
2. 外层 Agent 生成候选选题、受众、角度、证据映射和结构化 Content Spec，CLI 校验后提交选题批次。
3. Agent 基于已批准选题生成文章、摘要、卡片文案、图片说明和音视频脚本；CLI 校验来源、目标、资产清单和内容谱系。
4. 图片、语音、视频与平台渲染由外部 CLI、MCP 或 Agent 工具 Adapter 完成，CLI 只登记产物、hash、费用和来源。
5. 按公众号、小红书、网站、播客或视频等显式 Channel Adapter 构建发布包；对外发布默认保留人工确认和显式 apply。

同一机制还能生成个性化简报、课程与阅读路径、研究专题、FAQ、决策材料、关系图谱和其他基于知识图谱的应用。它们共享 Knowledge Pack、Artifact Manifest 和 prepare/commit 契约，只替换 Skill、Schema 与输出 Adapter。

这一阶段的完成标准是：合成知识库可以离线跑通“选题 -> 文章 -> 卡片 -> 发布包”；每个结果能追溯到知识来源和生成批次；重放收敛为 noop；中断可以从最后一个已提交阶段恢复；没有 Agent 或媒体工具时返回明确的待处理状态。详细设计见 [`knowledge-applications.md`](knowledge-applications.md)。

## 后续阶段：个人产品外壳

可以在当前核心之上提供桌面端或本地 Web 产品，负责：

- 安装、自检和外部 CLI 认证引导。
- vault 选择、配置编辑和能力发现。
- 候选批次预览、diff、审批与显式 apply。
- 选题、内容、媒体资产与发布包的流水线视图。
- Job 接入、运行记录、失败诊断和通知。
- Skills、Agents、Provider 与宿主适配器的可视化说明。

产品外壳只调用 CLI JSON、读取 Jobs 或连接本地 MCP，不复制路径保护、校验和写入逻辑。第一形态应保持 local-first，不要求账号或云端数据库。

## 长期方向：可选的协作与托管

在个人本地闭环稳定后，才评估：

- 多设备同步与加密备份。
- 团队共享知识空间、审阅和权限。
- 托管调度、远程通知和运行观测。
- 经过审核的 Provider、Skill 与模板分发。
- 可选的内容协作、渠道分发和知识应用模板市场。
- 面向组织的策略、审计和合规控制。

这些能力必须是独立模块。任何远程形态都要显式说明数据流向、存储位置、费用、副作用和退出方案，不能让本地 CLI 在无感知情况下联网或上传 vault。

## 进入核心的判断标准

一项能力只有同时满足以下条件才进入确定性核心：

1. 多个宿主都需要，而不是某个产品界面的专属便利功能。
2. 输入、输出、错误和副作用可以写成稳定契约。
3. 无模型也能离线测试。
4. 不要求隐藏凭证或私有服务成为基础依赖。
5. 能保持 preview、显式 apply、路径保护和幂等语义。

不满足这些条件的能力应留在 Skill、适配器、Job 或产品外壳中。这样产品可以增长，核心接口仍然小而稳定。
